## 坑与发现
1. **「git 推送成功」≠「线上更新」**：昨晚两条 push 都是 main -> main，但 Pages 构建 errored + 一条卡死在 building，线上一直停在第十三轮。以后发布后必须查 `gh api repos/<repo>/pages` 的 status 与线上文件大小/构建戳，不能只看 push 输出。
2. **Pages 卡住的构建可以手动重发**：`gh api -X POST repos/lb290/code-animation/pages/builds`，不必空提交一次；重建后 20–30 s 生效（CDN 再等几十秒）。
3. **构建戳一定是「提交前」的 HEAD**：`build.mjs` 用 `git rev-parse --short HEAD` 打戳，而 HTML 又要和代码进同一个提交 → 页面上永远比 HEAD 落后一格。这次为了让手机端版本自查对齐，是在 99f2cad 之后又重建了一次（戳 = 99f2cad），文档提交只改文档。判断「是不是最新」用三角数 + 观景点/抄本页数，比只看短哈希可靠。
4. **手机可能拿到旧缓存**：PWA 的页面导航是网络优先，但离线包要换 VERSION 才会更新；这次升到 v14。若打开还是旧版，先下拉刷新，再不行清站点数据。

## 坑与发现
1. **"文件太大"要拆成三件事看**：成品字节（网页 gzip 356 KB 不算大）、构建成本（2.16M tri 已到软上限）、
   仓库卫生（10 个过期分文件 8.15 MB 才是真的臃肿）。用户感觉到的"大"其实是三件事的叠加。
2. **等距圆柱投影的星场会在天顶长出"幕布竖纹"**：第一版 starLayer 用 (atan2(z,x), asin(y)) 网格，相机仰视时
   格胞被压缩成整屏竖条纹（core 排查半天以为是他的几何，最后靠 `no=world` 才定位到天空）。改成**三维格点**后消失。
3. **无头截图会带"标题页鬼影/ HUD 重影"**：CSS 过渡中的标题页在某些合成器组合下会被截进画面。修法：
   `?noui` 时 `hideLoading(true)` 直接把 `#loading` 设 `display:none`，不走 1.4 s 过渡；截图前多等 1 s 也更稳。
4. **并行子代理抢 CDP 端口**：几个 agent 同时跑 `shot.mjs`（默认 9333）会互相串台（截到别人的标签页/不落盘）。
   给每个 agent 在提示词里写明用独立 `--port`；lead 自己做最终截图时也逐个换端口。
5. **触屏摇杆"前进/后退"方向要对着 touch.js 的约定**：`z = -dy/R`（屏幕往下 = 后退），相机里必须是 `az + tz`；
   写成 `az - tz` 会出现"往上推反而后退"。mobile-check 靠"位移 > 0.5 m"能抓到量，但抓不到方向 —— 方向要人看。
6. **`?from=easel` 不要再让用户点第二次**：从画里坠入后如果还停在标题页等「坠入星海」，等于两次点击才进世界；
   改成 `ready()` 里 `?from=easel` 自动 `startExperience()`（0.7 s 后），标题页当出生字幕淡出。
7. **观景点是"相机在几何里"的重灾区**：view 3 最初 `y=-34` 落在对接舌台甲板下面（看到的是腹面），
   view 6 原本想拍鲸骨却对着辐条。定机位必须实拍，不能靠坐标想当然。
8. **文案/记录工具的引号坑**：写 Markdown 时把反引号塞进 JS 模板字符串会截断脚本（本轮踩过一次，
   一度把 HANDOFF 写短了 46 KB —— 已 `git checkout` 还原，改成"写临时文件 + node 拼接"的方式追加）。
