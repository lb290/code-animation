## 坑与发现
1. **「git 推送成功」≠「线上更新」**：昨晚两条 push 都是 main -> main，但 Pages 构建 errored + 一条卡死在 building，线上一直停在第十三轮。以后发布后必须查 `gh api repos/<repo>/pages` 的 status 与线上文件大小/构建戳，不能只看 push 输出。
2. **Pages 卡住的构建可以手动重发**：`gh api -X POST repos/lb290/code-animation/pages/builds`，不必空提交一次；重建后 20–30 s 生效（CDN 再等几十秒）。
3. **构建戳一定是「提交前」的 HEAD**：`build.mjs` 用 `git rev-parse --short HEAD` 打戳，而 HTML 又要和代码进同一个提交 → 页面上永远比 HEAD 落后一格。这次为了让手机端版本自查对齐，是在 99f2cad 之后又重建了一次（戳 = 99f2cad），文档提交只改文档。判断「是不是最新」用三角数 + 观景点/抄本页数，比只看短哈希可靠。
4. **手机可能拿到旧缓存**：PWA 的页面导航是网络优先，但离线包要换 VERSION 才会更新；这次升到 v14。若打开还是旧版，先下拉刷新，再不行清站点数据。
