### 硬边界（必须遵守）

1. **每个 b.push() 必须配对 b.pop()**；矩阵 16 float；构建完 `b.stack.length === 1`。
2. 颜色是 3 个线性 rgb（PC.*），材质是 2 元组（PM.*/MT.*）；**不能把材质数组当颜色**。
3. 随机数只用传入的 rng（mulberry32），禁止 Math.random。
4. 内表面法线必须朝房间内侧；外表面逆时针朝外；退化三角形避免。
5. 虚拟净空：大门通道内、圆厅空腔（r<11 于 (0,44,144)）、采光洞（(0,76,144) r<5.0, y>69）
   不允许有顶点。
6. 只写自己的文件；world.js / palace-plan.js / layout.js / 别人的模块只读，要改先找 lead。
7. 别写 `04-output/CIELO.html`（lead 的最终产物）、别跑 final-stills。

### 各自的最低验收

- `node tools/<module>-check.mjs` 打印 PASS（栈平衡 / 无 NaN·bad colour·bad normal / 包围盒 / 面数 /
  确定性 / 各自的净空断言）。
- 用自己的 `--as` 构建 + `tools/look.mjs` 拍 5–10 个机位，`read_image` 亲眼确认：
  外观看「露台用户视角 / 城市地面仰视 / 侧面 / 高处鸟瞰 / 穿过大门往里 / 远景穹顶」；
  圆厅看「门厅往里 / 仰望穹顶 / 厅内回望大门 / 后龛彩窗 / 采光洞俯视 / 大门口全景」；
  写生角看「官方少女机位不挡人 / 写生角全景 / 圆桌椅 / 画架细节 / 宫殿前回看」。
- 最终消息给 lead：文件、三角形数、包围盒、静帧路径、风险与未完成项。
