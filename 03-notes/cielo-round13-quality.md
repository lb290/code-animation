# CIELO · 第十三轮：画质系统 v2（手机端「不糊了」）

> 2026-11-25 晚 · 用户：「现在手机上打开不会卡死了，但是建筑的显示效果非常粗糙，你继续优化显示效果，
> 既要流畅，又要精细分辨率高。」配图是一张手机横屏截图（HUD 显示 `60 FPS / 2.5 ms cpu / 2049k tris`），
> 画面是宫殿门厅，柱子/栏杆/金饰全是 3–4 个像素的大方块。
>
> 这一轮不是加内容，是把**渲染分辨率与后处理管线**重做：先量出「粗糙」的来源，再按像素预算 +
> 自适应分辨率 + 输出分辨率锐化把它修掉，并用图像指标验收。产品方案 C「游客护照」/ D「语音导览」
> 继续排在下一轮（见 [cielo-product-ideas.md](cielo-product-ideas.md)）。

## 1. 量出来的根因（不是猜的）

`tools/quality-check.mjs`（本轮新增）在手机仿真视口（1280×582 CSS，dpr=2，`?q=low`）截 2560×1164
设备像素图，纯 Node 解 PNG 后算指标。第 12 轮构建（`05fbc06`）的读数：

| 指标（手机 4 视图均值） | 第 12 轮 | 说明 |
|---|---|---|
| 渲染缓冲（画面真实分辨率） | **768×349 = 0.27 MP** | 被放大 **3.33×** 才到 2560×1164 |
| 相邻像素完全相等比例 | **28.4%**（纹理区 9.4%） | 上采样放大 → 成片重复块 |
| 2×2 同色块比例 | **11.0%** | 「粗糙」的直接量化 |
| 锐度 Laplacian 方差 | 115.7 | 桌面 1:1 是 1283.8 |
| 边缘对比 p95 | 112.2 | 桌面 146.8 |

**根因三条，都在 `src/main.js`：**

1. `resize()` 里 `canvas.width = innerWidth * W.scale`，**完全没算 `devicePixelRatio`**。旧低画质档
   `scale=0.6` 在 dpr=2 的手机上等于：场景渲染 0.87 MP → 合成写进 0.6×CSS 的小画布 → **浏览器再把它
   双线性放大 3.3 倍**铺满屏幕。所以「不卡」是拿分辨率换来的，换得太狠。
2. 低画质档 `fxaa: 0` —— 恰恰是最需要抗锯齿的档位没有抗锯齿。
3. 自适应只有「开局 150 帧测一次、只降不升」，而且档位的 `max` 就锁死在 0.68：能跑的手机也永远
   停在 0.6 倍率。分辨率没有任何「长回去」的路径。

## 2. 方案（做了什么）

### 2.1 分辨率模型：把「输出」和「场景内部」拆开

- **输出画布**：按设备像素出，`outScale = min(devicePixelRatio, 2)`，再受档位 `outCap` 限制
  （low 2.2 MP / mid 2.7 MP / high 3.4 MP）。dpr≤2 时画布与屏幕 **1:1**，浏览器不再参与放大。
- **场景内部**：`scenePx` 像素预算（low 0.55–1.7 MP / mid 0.78–2.3 MP / high 0.9–3.2 MP），
  实际尺寸 = `min(预算, 输出像素)`。预算保留原值，转屏/拉大窗口后能自己长回去。
- `W.scale` 现在是「场景像素 / CSS 像素」，`__cielo.stats()` 另有 `outW/outH/outPx/scenePx/sceneEff`。

### 2.2 后处理两段式：内部合成 → 输出分辨率放大+锐化

旧管线只有一段 composite，直接写进小画布；放大交给浏览器（双线性，3.3×，没有锐化）。
新管线两段：

1. **composite**（场景内部分辨率，HDR → LDR）：FXAA + bloom + 曝光 + 色调映射 + 饱和度/对比度；
2. **upscale**（输出分辨率，新 `src/glsl/upscale.fs.glsl`）：双线性采样 + **4 tap unsharp**
   （锐化强度按档位 0.28–0.55，专补低分辨率上采样的糊；高光/暗部自动回退避免白边黑边）+
   晕影 + 颗粒 + 抖动（`1/255` dither 消色带）。

FXAA 三档都开（旧版 low 是关的）。晕影/颗粒从内部搬到输出分辨率，不会被放大成色块。

### 2.3 自适应分辨率：GPU 计时器 + 双向调节

- 用 `EXT_disjoint_timer_query_webgl2` 量**真实 GPU ms**（每帧一个 query，下一帧取），
  避开 vsync 把帧时间量化成 16.7/33.3 ms 的问题；没有该扩展就退化到帧时间判定。
- 每 30 帧一个窗口：`gpu > 目标×1.08` → 场景预算 ×0.86；`gpu < 目标×0.80` → ×1.05（降快升慢，
  冷却 3/5 个窗口）。三档目标 12.5 / 13.5 / 14.5 ms（60 fps 一帧 16.7 ms，留抖动余量）。
- **找到的最优点按档位写进 `localStorage`（`cielo.px.v2`）**：同一台设备第二次打开直接从上次的
  最优点开始，不用每次重新摸索。
- 最后一道保险：场景预算已经到 `pxMin` 还超预算，说明瓶颈在输出分辨率的放大 pass → 把
  `outMul`（0.62–1.0）往下调，输出分辨率字面降低（`?gputarget=<ms>` 可强制目标，验收用）。
- 旧版「只降不升」删掉了；开局仍有 160 帧的探测期（只记录、不调档），<30 fps 时开局自动降一档
  （不写入 localStorage，用户显式选的档位下次仍生效）。

### 2.4 顺手砍掉的填充成本：天空改为「实体之后画，只着色露天像素」

天空 shader 里有 ~380 次噪声采样/像素（两层积云 + 卷云 + 星空）。旧顺序是**先全屏画天空、
再让建筑盖上去**——室内机位等于把整屏最贵的 shader 白算一遍。现在天空顶点 z 固定 1.0（= 清屏
深度）、在实体几何之后用 `LEQUAL` 只画深度仍为 1.0 的像素：室外省掉建筑遮挡部分，室内省 90%+。
**逐像素一致**（view 0 同机位 max diff 1，mean 0.0）。

### 2.5 三档 + 交互

| 档位 | 场景预算 | 输出上限 | 点光 | 阴影 | 锐化 | GPU 目标 |
|---|---|---|---|---|---|---|
| 流畅 low | 0.55–1.70 MP | 2.2 MP | 8 | 关 | 0.55 | 14.5 ms |
| 均衡 mid | 0.78–2.30 MP | 2.7 MP | 10 | 关 | 0.42 | 13.5 ms |
| 精细 high（触屏默认） | 0.90–3.20 MP | 3.4 MP | 12 | **桌面**才开 | 0.28 | 12.5 ms |

- 触屏默认「精细」：实测精细档（1.9 MP 场景 + 输出=设备像素）比均衡档锐度高一倍；
  跑不动的设备由开局探测降档 + 自适应兜底。触屏上任何档位都**不开阴影**（2M tri 的第二次整场景
  绘制是与分辨率无关的固定成本）。
- 触屏动作条新增「画质」按钮（流畅 → 均衡 → 精细，选择持久化到 `cielo.q.v1`）；桌面 `V` 键；
  `?q=` 仍可强制；`?px=` 强制场景预算（调试）。

## 3. 验收数据

### 3.1 图像指标（`tools/quality-check.mjs`，手机 4 视图均值 / 桌面 2 视图均值）

| 指标 | 手机 第 12 轮 → 本轮 | 桌面 第 12 轮 → 本轮 |
|---|---|---|
| 相邻等值% | **28.39 → 15.95（−43.8%）** | 8.69 → 8.66 |
| 纹理区重复% | 9.41 → 2.44（−74%） | 2.94 → 1.25 |
| 2×2 同色块% | **11.01 → 3.33（−69.7%）** | 0.35 → 0.69 |
| LapVar 锐度 | **115.7 → 225.2（+94.6%）** | 1283.8 → 2061.5 |
| 边缘 p95 | 112.2 → 139.3（+24.2%） | 146.8 → 165.5 |
| 渲染缓冲 | 768×349 → **2437×1108（1.41× 上采样）** | 1280×720（1:1） |

> 手机「渲染缓冲」baseline 是 768×349（3.33× 上采样）；本轮默认档是 1723×783 → 2437×1108
> （1.41× 上采样 + 输出分辨率锐化）。

三档在同一手机视口（view 0）的差别，说明档位是真的在起作用：

| 档位 | 输出 | 场景 | LapVar | 2×2 同色块% |
|---|---|---|---|---|
| 流畅 | 2200×1000 | 0.95 MP (1445×657) | 227 | 3.29 |
| 均衡 | 2437×1108 | 1.35 MP (1723×783) | 259 | 3.14 |
| 精细 | **2560×1164（= 设备像素）** | 1.90 MP (2044×929) | **463** | **1.29** |

锐化副作用检查：尖塔/金饰/窗框 6× 放大无成圈白边/黑边，过冲像素手机 0.05/0.08% → 0.09/0.16%，
桌面 0.29/0.36% → 0.40/0.49%。

### 3.2 成本曲线（`tools/perf-split.mjs`，headless desktop GPU）

- 拟合 `frame_ms ≈ 4.09 + 2.83·MP`（R²=0.99）：**填充率主导**（几何固定成本 ~4 ms）。
- 关静态世界反而更慢：没有世界做遮挡，天空/云要全屏着色 —— 与 2.4 的改动同向。
- 后处理 1 MP ≈ 2.5 ms 上界（bloom 只占 0.2 ms）；输出分辨率每多 1 MP 边际 0.2–0.6 ms。
  手机端把 composite/放大抬到 ~3 MP 预计 3–12 ms（桌面 ×3–10 的经验外推），有 `outMul` 兜底。

### 3.3 回归

- `checkall` **30/30 PASS**（几何/数据一字未动）。
- `mem-check` / `mobile-check`：见 STATUS 事实块与提交信息（本轮同步更新了 mobile-check 的画质断言）。
- 桌面：dpr=1 时输出仍 1280×720 1:1，几何与配色不变；upscale 的锐化在 1:1 下是温和锐化，
  LapVar 1283.8 → 2061.5（更锐，桌面观感提升，无几何/颜色变化）。

## 4. 试过但放弃：背面剔除

几何大多是封闭实体，理论上 `CULL_FACE` 能省一半顶点/光栅化。实测（`?cull=1` 临时开关）：
view 0 有 12.4% 像素差（>8）、view 40 有 28.3%，放大看图是**墙上出现洞** —— 各模块 winding
不一致（还夹杂单面片：纸、旗、玻璃）。修 winding 等于重写全部 module 的顶点顺序，风险远超收益。
开关已删除，这条决定写在这里，避免下一轮再试一遍。

## 5. 已知限制 / 下一轮

1. **真机帧率仍未测**：本轮只有桌面 GPU 的 GPU ms 与拟合曲线。请真机 `?perf`（HUD 现在显示
   `FPS / gpu ms · cpu ms / 场景 MP · 输出 MP`）记录 杂乱场景/室内 两组，写回 STATUS。
2. **输出放大 pass 的成本上限**：2.2–3.0 MP × 5 tap 在极弱 GPU 上可能占 3–10 ms；已用
   `outMul` 兜底，但首次打开可能先抖 1–2 秒（自适应收敛期）。
3. **场景预算的默认值是按桌面 GPU 数据外推的**：真机若显示 `sceneEff` 明显低于 `px0`，
   可以把 TRIM 的 `gpuMs` 或 `px0` 调低；反之调高。
4. **画面仍有 1.4× 上采样**：手机默认档做不到 1:1（1:1 需要 ~2.6–3 MP 场景，2M tri 的设备扛不住）；
   「精细」档可以到 1:1。再往上要等几何降级（第十二轮遗留：移动端城市减细分）。
5. **画质档位持久化是设备级**：同一台手机换了档，下次打开沿用；删 localStorage 恢复默认。
6. 天空后置后，若将来有「半透明但写深度」的物体在天空之前，需要复查顺序。
