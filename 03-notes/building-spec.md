## 0. 怎么读参考图（测量方法与四个标定平面）

参考图是**极端广角 + 低机位**的插画：同一栋楼上，檐口、挑台、招牌处在三个不同深度，
屏幕像素不能直接互比（同一根柱子，近平面比远平面粗 2 倍）。所以先把画面切成 **4 个测量平面**，
每个平面单独标定「1 间 = 多少 px」，**构件只在本平面内换算**。

| 平面 | 图上区域（原图坐标） | 标定锚点（读数） | 反推比例 | 1 间（2.0 m） |
|---|---|---|---|---|
| **N** 右近景大楼 | x 1540–1761，y 60–200 | 椽头中心距 43 px ↔ 0.34 m；瓦行法向距 46 px ↔ 0.36 m | 126–128 px/m | **254 px** |
| **L** 左近景长立面 | x 40–620，y 0–560 | 大格子 40–55 px ↔ 0.45–0.55 m；竖棂 9–11 px ↔ 0.10 m | ≈100 px/m | **200 px** |
| **M** 中景挑台町屋 | x 620–1160，y 380–700 | 低栏杆通高 57 px ↔ 0.65 m；檐下灯笼 Ø40 px ↔ 0.45 m | 82–95，取 88 px/m | **176 px** |
| **F** 远景钟楼 | x 1180–1410，y 0–260 | 钟面 Ø145 px ↔ 1.5–1.7 m | ≈90 px/m | ≈185 px |

标定过程（可复核）：

- **N**：檐口一排椽头，中心距 43 px。唐样 / 和风椽距实建 0.32–0.40 m，取 0.34 m ⇒ 126 px/m；
  同一檐口的瓦行（平行檐口的瓦垄线，2D 频谱主峰周期 46 px）按 0.36 m 计 ⇒ 128 px/m。
  两者差 <2% ⇒ 取 **127 px/m（1 间 = 254 px）**。
- **L**：上部近景立面的障子格子 40–55 px 宽、竖棂 9–11 px。按格子 0.45–0.55 m、棂 0.10 m ⇒ ≈100 px/m。
- **M**：中景挑台的低栏杆通高 57 px，按和风低栏 0.60–0.70 m ⇒ 81–95 px/m；
  同平面檐下灯笼 Ø40 px 按 0.45 m ⇒ 89 px/m。取 **88 px/m（1 间 = 176 px）**。
- **F**：远景钟楼钟面 Ø145 px。装饰塔钟实建 1.5–1.7 m ⇒ 85–97 px/m，只作量级参考。

三条读数规则：

1. **只在本平面内换算**。跨平面必错（近平面 254 px/间 vs 中景 176 px/间，差 1.44 倍）。
2. **投影长度只当下界**。仰视 / 俯视会把出檐、挑台、踏步在屏幕上压短，读到的值 ≤ 真值。
3. **插画夸张 1.2–2 倍**（柱径、灯笼、斗拱尤其明显）。**场景取值 = 读数 ×0.8–1.0，再收到实建区间**；
   只有小构件（椽头、棂条）为了在 720p 下仍可读，允许放宽到 ×1.5。
   本文 §3 的「场景采用」列已经是收敛后的值，不要直接拿参考图读数建模。

## 1. 现状差距（对照 02-street / 08-tower）

`world.js:118` 的 house() 现在做的是：台基 box + 两段换色墙 box + 4 根角柱 + roof() + 3 块 0.08 m 厚发光窗片 + 门 + 2 盏灯笼。
逐条对参考图：

| 现状 | 参考图 | 差距 |
|---|---|---|
| 屋顶直接从墙顶起坡，檐口是 roof() 的 lip 薄片（0.55 宽 × 0.35 高） | 深檐：檐口厚 0.22–0.28 m，檐下露椽头阵列、下有白壁小壁 | **没有「檐」这个物体**，只有一条亮边 |
| 窗是贴在墙外的 0.08 m 亮方块 + 1 根横棂 | 格子窗：窗框、内凹、窗台、竖棂阵列 | 近看是「亮贴纸」 |
| 立面上下两段换色，无柱位 | 柱 / 长押 / 梁把立面分成 2–4 间 | 没有分间节奏，像仓库 |
| 只有灯笼 | 挑台 + 栏杆、暖帘、招牌、幡旗、雨棚 | 人尺度构件整体缺位 |
| 台基是 0.7 高光 box | 台基 0.45–0.60 + 踏步 + 线脚 / 须弥座 | 没有落地感 |
| 24 栋同一拓扑、屋顶同一曲率 | 每栋面宽 / 层数 / 屋顶 / 窗型都在变 | 镇子像「一排小盒子」 |

**结论**：不是「加细节」，而是先做三件事——**立模数（1 间 2.0 m）、补「檐」这个物体、补分间与挑台**。
其余（斗拱、悬鱼、瓦当、雕花）按 LOD 加或不加。
`02-street.png` 右侧那块顶到天的大红墙，就是「墙直接接屋顶、没有檐口过渡」的最坏情况。

### 2.1 读图结论（这五条决定「像不像」）

1. **立面的「层」来自三个深度**：檐口（外挑 1.0–1.3 m）、挑台（0.65–0.8 m）、招牌 / 幡（再外挂 0.15–0.5 m）。
   盒子贴窗永远做不出层——先做挑出的构件，再谈贴图。
2. **深檐是主特征**：檐口厚 0.22–0.28 m、椽距 0.36 m、檐下小壁 0.30–0.45 m。
   这三件套在参考图里出现频率最高、也最省面数。
3. **竖线打断横线**：柱、幡、挂灯、竖匾四种竖向元素穿过檐口，是「街」而不是「墙」的关键。
   只做横的檐线，再精致也像展板。
4. **明暗节奏**：深檐把立面压成 2–3 条暗带，窗纸 / 灯笼是亮点。立面大致 **40% 暗、50% 中调、10% 亮**。
   夜景下没有暗带，细节全被城市暖光洗平。
5. **材质反光要分开**：瓦冷青灰（月光）、木暖褐、朱漆 / 金饰有高光、窗纸自发光。
   参考图里**瓦比木墙亮且冷**；现状是反的（`C.roof` 暖棕 #5a3a30，和木墙同色）——这是「一看就假」的隐性原因。

> 只取建筑语言：**不复制参考图的角色、文字内容、招牌文案与鱼灯**；招牌只做「有字感」的抽象纸牌（见 §3.7）。

### 3.4 屋顶：坡度、举折与脊高

- 主檐半跨 **L = 进深/2 + 出挑** = 3.0–4.3 m；脊高 **H = L × 0.55** ⇒ 1.65–2.35 m。
- 举折（反宇）：**脊段坡度 0.68–0.78、中段 0.55、檐口段 0.30–0.40**。
  对应 `geo.js roof()` 的 `curve` **取 1.25–1.35**（不是现在的 1.55；
  1.55 在檐口几乎水平，看着像软塑料），再叠 `lip`（翘角）：`lipH 0.32–0.40, lipW 0.35`。
- 瓦行（平行檐口的瓦垄线）**0.30–0.34 m 一道**，用逐行色带（邻行亮度差 15–20%）+ 近景 hero 才加 0.10 m 薄瓦当条；
  不做单颗瓦当。
- 屋脊：脊瓦压顶 0.18–0.22 高，端部鬼瓦 / 悬鱼 0.25–0.35；**脊是屋面的收头，不是一条黑线**。
- 屋顶类型：切妻为主（沿街长边起脊），入母屋只给 hero 和 3 层；**不做歇山/重檐塔楼**（钟楼、五重塔维持现状）。

### 3.5 挑台与栏杆

- 台板：厚 0.12–0.15、出挑 0.65–0.8；台板下 2–3 根挑梁（0.10×0.18）露出，末端切角。
- 栏杆三级：**扶手 0.08–0.10 见方 / 下枋 0.10×0.08 / 棂条 0.04×0.04、间距 0.22–0.28**；
  望柱 0.09 见方 ×0.95，间距 1.6–2.0（≈ 1 间/2）。
- 栏杆两端必须收到柱身或墙垛，**不许悬空**；栏下墙面用顶点色压暗（×0.62）当投影。
- 挑台只做二层朝街面 + 端部转角，不做四面环绕（面数 + 穿帮）。

### 3.6 窗型库（同一立面至少 2 种）

| B 虫笼窗 | 0.9 × 0.6 | 1.40–1.60 | 二层侧墙 / 檐下 | 竖棂 10 根 ×0.03，间距 0.09（细密感） | ~80 |

### 3.8 布局适配（现状 `world.js:664-694`）

## 4. 色板（夜间 / 线性空间）

### 4.1 用色规则（先读这段，再看表）

- 管线：顶点色直接写**线性值**；`geo.js rgb(hex)` 已经把 sRGB hex 转线性。`mat = (emissive, gloss)`。
- `LIT_FS`（`shaders.js:77-150`）实际计算：
  `lit = albedo·(key + amb + cityGlow + pl) + spec·albedo·3 + albedo·emissive·2.6 + (1,0.72,0.42)·emissive·0.55`，
  之后过 ACES + bloom（阈值 0.88）。
  ⇒ **emissive 乘 2.6 再加暖芯**，emissive=1 时已经接近满白；窗纸不要超过 1.0。
- 反照率目标（线性亮度 Y，`0.2126R+0.7152G+0.0722B`）：

| 材质 | Y 区间 | 说明 |
|---|---|---|
| 木（柱/梁/椽/栏杆） | **0.02–0.10** | 超过 0.10 会被城市暖光洗成「橙纸片」；主柱用 0.05–0.08 |
| 灰泥 | **0.20–0.45** | 夜景里最亮的大面；用 0.40 左右，靠 AO 压暗部 |
| 瓦 | **0.05–0.10** | **冷色**，略亮于木；这是「瓦 vs 木」的分界 |
| 石 / 台基 | **0.08–0.25** | 台基 0.08–0.12，踏步受光面 0.20 |
| 金 | **0.35–0.50** | 靠 gloss 出高光，不靠亮度 |
| 窗纸 | 0.65–0.75（albedo）+ emissive | 亮度主要由 emissive 给，albedo 只定色相 |

- 推荐参数带：

| 类别 | emissive | gloss |
|---|---|---|
| 窗纸（普通 / 亮） | **0.45–0.55 / 0.80–1.00** | 0 |
| 灯笼纸 | **0.80–1.00** | 0 |
| 金饰 | **0.12–0.25** | **0.65–0.80** |
| 朱漆柱 / 栏杆 | **0.02–0.04** | **0.30–0.38** |
| 木 | 0–0.02 | 0.08–0.16 |
| 瓦 | 0 | 0.18–0.28 |
| 灰泥 | 0 | 0.03–0.06 |
| 布（暖帘 / 幡） | 0–0.03 | 0.02–0.05 |
| 石 | 0 | 0.08–0.15 |

- **同亮度不连片**：相邻材质 Y 至少差 1.5 倍；每栋按 seed 抖动 ±6%（木）/ ±4%（瓦）。
- 顶点色 AO（没有阴影贴图时唯一便宜的体积感）：檐下 ×0.58–0.65、柱脚 ×0.70–0.78、窗洞内 ×0.50，
  **窗纸自发光不乘 AO**（否则灯会跟着暗）。

## 6. 静帧验收判据（对 02 / 03 / 04 / 08 逐条打勾）

- [ ] **1. 檐口有厚度**：`02` 近景任一栋，檐口在 1600×900 下 ≥8 px 厚，能读出
      「瓦口 / 封檐板 / 椽头阴影」≥2 层；不是一条 1 px 亮边。
- [ ] **2. 椽头阵列**：hero 栋正面檐下可数 ≥12 根椽头，**间距均匀**（0.32–0.42 m 投影），

- [ ] **8. 明暗层次**：立面上木（Y 0.02–0.10）/ 灰泥（0.20–0.45）/ 瓦（0.05–0.10）三档可分；

- [ ] **10. 性能与规模**：hero ≤4k / mid ≤1.5k / far ≤300 tri；台基不穿地、不悬空；

## 7. 不要做（性价比低 / 过拟合）

1. **不做真实的 7 铺作斗拱 / 逐层出跳**。参考图里斗拱只是檐下的浅色小方块，读不出层数；
   3–5 段简化（≤360 面）就够，hero 以外不做。
2. **不做单颗瓦当 / 滴水的独立几何**。用逐行色带 + 檐口 0.10 m 薄瓦当条代替，省 3–5 倍面；
   近景也读不出单颗。
3. **不做真窗洞 / 室内**。用「内凹 0.05–0.08 m 的暗腔 + 自发光窗纸」假内凹；
   真穿孔会引出双面、深度排序、背面剔除三个坑，而游客看不到室内。
4. **不给建筑做贴图 / UV / 法线贴图**。零素材约束 + 单文件预算是硬约束；顶点色 + 程序化色带已经够。
5. **不做逐栋唯一纹样**。窗棂 / 斗拱 / 幡色只用 3–4 个种子，靠面宽 / 层数 / 屋顶 / 窗型组合出变化；
   逐栋雕花会让代码膨胀、面数失控。
6. **不做 CSM / 阴影贴图**。夜景月光弱，阴影几乎看不见；用顶点色 AO 带（檐下 ×0.6、柱脚 ×0.75）代替。
7. **不复制参考图的角色、文字、招牌文案、鱼灯**。只取建筑语言；招牌只画抽象色块 / 笔画。
8. **不做布片物理 / 风摆**。暖帘、幡、灯串全静态（或 ≤0.02 幅度慢摆）；
   单层薄片一摆就露馅，而且每帧要更新顶点。
9. **不做 3 层以上 / 重檐塔楼 / 歇山**。钟楼、五重塔维持现状只补檐口细节；
   建筑主体最多 3 层，屋顶最多入母屋。
10. **不做 0.02 m 级线脚 / 雕花 / 门钉阵列**。飞掠视角看不见，面数翻倍；只做 ≥0.06 m 的构件。
11. **不做室内 / 家具 / 可开合门窗 / 碰撞**。场景是外观巡游。
12. **不要把面宽压到 3 m 以下**。夜景里街道会变成夹缝，且鱼灯（30 单位）从街上过不去；
    4.6 m 是底线。

### 8.2 `world.js` 用 `buildMachiya(o)` 替换 `house()`

```js
buildMachiya(b, ctx, {
  bays: 2 | 3,          // 面宽 = bays*2.0 + 端柱
  floors: 1 | 2 | 3,
  depthBays: 2 | 3,     // 进深 = depthBays*2.0（2 间取 4.6–5.2）
  roof: 'kirizuma' | 'irimoya',
  balcony: false | true,
  hisashi: false | true, // 腰檐
  windows: ['A','B','C','D'], // 立面窗型分配
  lanterns: 2 | 3,
  detail: 'hero' | 'mid' | 'far',
  seed,                  // 色抖动 / 窗型 / 幡色
})
```

每栋返回 `{ w, d, h, tris }` 方便预算统计；`house()` 保留一版兼容，样板定型后删。

### 8.3 顺序

1. **1 栋样板**：主街第一栋，面宽 6.4（3 间）/ 2 层 / 挑台 / 腰檐 / A+B 窗 —— 定比例、材质、面数（目标 ≤3.4k）。
2. 拍近景（`?freeze=6&cam=...&look=...`）对照参考图调一轮：檐口厚、椽距、栏杆高度、窗纸亮度。
3. 主街 4 栋 hero → 16 栋 mid → 12 栋 far；每档一次 `bench` + 视锥统计。
4. 验收 §6，把 02 / 03 / 04 / 08 重拍；`CELESTIA.html` 体积、bench、面数三条红线一起看。

**实现时发现的两个新增结构约束（写进 `HANDOFF.md` §4）**

1. 有挑台的楼层在**核心体之外**再建一道内退的 2F 墙，核心体必须内缩到 `d-1.0`，否则窗纸被核心体吃掉。
