# CIELO 产品改进方案 · PRODUCT IDEAS

> 规则：每轮**列出两个**候选方案，**推进一个**（做到能验收、能演示），另一个留在本文件等下一轮。
> 判断标准：① 对"来逛一座城"的人有真实价值；② 复用现有系统，不另起一套；③ 验收可判定（能写进 checkall / mobile-check）；④ 桌面体验零回归。

## 已完成

### 方案 A · 明信片工坊（Postcard Atelier）—— Round 11 推进 ✅

**问题**：这座城很好逛，但逛完什么也带不走。用户会截图，截图里有 HUD、有卡片，不像纪念品；在平板上也没有"分享给朋友"的顺手动作。

**方案**：任何机位按 **C**（触屏「明信片」按钮）→ 暂停这一刻，生成一张 1440×960 的明信片：
- 纸边 + 金色内框 + 院徽菱形 + 编号（POSTCARD No. 月日）；
- 画面用 `gl.readPixels` 取 WebGL 帧缓冲，**不带任何 UI**；低画质档下临时抬到 1.0 倍渲染一帧再截（只多一帧，不改用户的画质设置）；
- 地名按城区锚点判断（露台 / 大道长街 / 中央广场 / 王宫 / 玻璃宫 / 大教堂 / 高架车站 / 歌剧院 / 巨鲸与鲸背城 / 云上茶席 / 云海），阈值之外写「云端漫游」，不张冠李戴；
- 落款：昼夜（白昼 / 黄昏 / 夜晚）+ 日期；
- 「保存图片」下载 PNG；「分享」走 Web Share API level 2（安卓 Chrome 支持直接分享文件），不支持时提示用保存。

**验收**：`tools/mobile-check.mjs` 断言打开明信片后 `#pc-img` 的 dataURL > 50 KB；桌面按 C 也能出片。

**后续可加**：3 套纸样/边框、加一句自选题词、明信片背面（竖排地址栏）、把「保存」接到系统相册（File System Access API）。

### 方案 B · 主题航线 · 导览巴士（Guided Routes）—— Round 12 推进 ✅

**做了什么**：`src/routes.js` 三条航线共 19 站（建筑朝圣 7 / 童话奇观 7 / 云端秘境 5，覆盖 16 个抄本页）；抄本头部「主题航线」面板 → 启程 → `cam.setView()` 逐站过渡 + 停留 12–16 s；顶部航线条显示「第 N / M 站 · 站名」，可暂停 / 继续 / 退出 / 读这一站；手动操作在镜头稳定 2.4 s 后被判「用户接管」自动退出。`?route=<id>` 直接启程。

**相对原方案的改动**：① 抄本**不自动翻页**（全屏面板会挡住这一站要看的画面），改成航线条上的「读这一站」按钮；② 退出航线**不恢复**原机位（停在当前站，按露台/观景键回）；③ 站间直线镜头过渡（不做避障）。

**验收**：`tools/routes-check.mjs`（数据：站数 / 机位 / 抄本 id / 停留 / 覆盖）+ `mobile-check`（启程 → 18 s 内推进到第 2 站 → 手动拖视角自动退出）。

**发现**：`src/lore.js` 的 `zone.view` 有多处与观景点序号错位（cathedral→43、opera→54、throne→25），航线按名字/语义配对、用 lore id 打开，不依赖 `zone.view`。

## 待推进（Round 14 候选二选一）

### 方案 C · 游客护照（Visitor's Passport）—— Round 13 首推 📋

**问题**：抄本有 31 页、观景点 80 个，逛完只留下「已读 4 / 31」这个数字；没有「我走完了这座城」的成就感，也没有可以带走的凭证。明信片工坊解决了「带走一张画面」，但没有解决「证明我来过」。

**方案**：把抄本的抵达记录变成一本护照：
- 每抵达一处（`guide` 的 `found` 集合）盖一个章，章面用该区域纹章 + 抄本编号；护照页在抄本里新增「护照」页签，按 9 个区域分页，集齐一区得一枚区域银章；
- 集齐 31 页 → 生成一张 **1440×960 的通关证书**：编号 / 地名 / 抵达日期 + 院徽压印 + 证书编号；复用 `postcard.js` 出片管线（readPixels + 纸边 + 金框），仍守「只取 WebGL 帧、不含 UI」的规矩；
- 进度复用 `localStorage` 的 `cielo.almanac.v1`（已存在），不新增存储键；`?passport=1` 直接出证（验收 / 演示）。

**验收**：新增 `tools/passport-check.mjs`（31 章齐全、9 区域分组正确、证书尺寸 1440×960）；`mobile-check` 增加「打开护照页签看到 N 个章 / 出证 dataURL > 80 KB」；桌面 `G` → 护照页签可用。
**风险**：证书是「截图 + 合成」，与明信片共用管线；低画质档要临时抬到 1.0 倍渲染一帧（明信片已有这段逻辑，直接复用）。

### 方案 D · 语音导览（Spoken Guide）—— Round 13 备选 📋

**问题**：抄本正文（景 + 故事，10,717 字）在平板上读起来累；安卓 Chrome 自带中文 TTS 却没人用。

**方案**：抄本正文顶部加「朗读这一页」按钮，用 Web Speech API（`speechSynthesis`，`lang: zh-CN`）念当前页的「景 + 故事」；朗读时高亮当前段、翻页自动停、再点停止；无中文语音包时静默降级成 toast「设备没有中文语音」。触屏与桌面同一套按钮。
**验收**：`?voice=1` 时页面自动朗读第一页（无头环境可能没声音，只断言 `speechSynthesis.speaking` 或降级 toast）；`mobile-check` 断言按钮存在、点击后状态变化、再点能停。
**风险**：音色取决于系统语音包，不同安卓 ROM 差异大。

## 备选池（还没排期）

- **时间流转**：白昼→黄昏→夜晚自动缓慢循环（10 分钟一圈），配「此刻该看什么」提示。
- **天气 / 云层变化**：云海高度随时辰变化，影响俯瞰效果。
- **分享链接**：把当前机位编码进 URL（`?cam=` 已有），做「把这一刻发给朋友」的短链。
- **航线扩写**：同一套 `routes.js` 数据结构再加 2–3 条（夜景线 / 儿童线 / 15 分钟精华线），`routes-check` 自动守门。
