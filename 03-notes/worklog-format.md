# 工作记录规范 · WORKLOG STANDARD

> 目的只有一个：**新会话打开仓库，3 分钟内知道"这是什么、现在什么状态、上一轮干了什么、下一步干什么、哪里有坑"**；三个月后回来查账也查得到。
> 规范是给未来的自己 / 另一个 agent 用的，不是给领导看的。写作标准：**事实、数字、路径、命令**。形容词不算记录。

---

## 一、四层记录，各管一件事（不许串岗）

| 层 | 文件 | 只写什么 | 生命周期 |
|---|---|---|---|
| **现状** | 根目录 `STATUS.md` | **现在**：线上是什么、本轮目标与进度、下一步≤5 条、硬约束、文档地图。**不写历史。** | 每轮改写；事实块由脚本生成 |
| **轮次历史** | 根目录 `HANDOFF.md` | 每轮的"现状（先读这段）/ 30 秒上手 / 已知遗留"。**只追加，不改旧轮**。 | 永久 |
| **会话日记** | `05-daily/YYYY-MM-DD.md` | 一段会话/一天：目标 / 做了什么 / 动了哪些文件 / 产物 / **坑与发现** / 下次接着做。 | 永久 |
| **施工合同** | `03-notes/<项目>-roundN-brief.md` | 开工前写：现状体检、验收标准（可执行）、实现顺序、测试方法、风险。**开工后冻结，不再改。** | 每轮一份，永久 |

写作顺序：**先合同（brief）→ 边做边留日记要点 → 收尾更新 STATUS + HANDOFF**。
`STATUS.md` 里的"事实块"（HEAD、工作树、成品大小、体检项数、观景点/抄本数量、最近日记）**不要手写**，运行：

> 事实块是**生成那一刻的快照**：刚提交完再刷新，它会显示提交前的 HEAD（差一格是正常的，以 `git log --oneline -3` 为准）。

```powershell
node tools/status.mjs --write     # 刷新 STATUS.md 的 AUTO 块并打印摘要
node tools/status.mjs             # 只打印，不改文件
```

---

## 二、命名与位置约定

- 轮次：`第 N 轮 / Round N`，从 1 开始；一轮 = 用户一次明确委托 + 一次推送。
- 日期：ISO `YYYY-MM-DD`，时间用北京时间 `HH:MM`。
- 合同：`03-notes/cielo-roundN-<主题>.md`（主题用英文小写连字符，例：`cielo-round11-android-tablet.md`）。
- 日记：一天一个文件；同一段会话续写同一文件，不新开。
- 图片/视频/成品 URL：**只写仓库相对路径**（`04-output/CIELO.html`），不写 `F:\\...` 绝对路径。
- 状态四符号：`✅ 完成` / `🚧 进行中` / `⏸ 暂停（等什么）` / `❌ 失败（原因 + 下一步）`。

## 三、每层必填段落

### 1. `STATUS.md`（一屏，读 90 秒）
```markdown
<!-- AUTO:START --> …自动事实块… <!-- AUTO:END -->
## 0. 一句话：这是什么
## 1. 线上入口（可直接点开）
## 2. 本轮（Round N · 日期）：目标 / 合同链接 / 进度清单
## 3. 下一步（≤5 条，具体到文件和动作）
## 4. 硬约束（违反就会返工的规则）
## 5. 新会话 3 分钟上手（读什么、跑什么命令）
## 6. 文档地图（哪个文件管什么）
```
> 规则：`STATUS.md` 里出现"上一轮""曾经"就说明写错层了，挪去 HANDOFF。

### 2. `HANDOFF.md` 每轮固定开头（≤20 行）
```markdown
# 交接 · <作品>（YYYY-MM-DD，第 N 轮：一句话主题）
> **用户原话**（逐字引，含日期）
## 第 N 轮现状（先读这段）
- 本轮新增/修改了什么（模块 + 数字：三角面、观景点、抄本页数、文件大小）
- 体检 N/N PASS、产物大小、线上是否已发布
## 第 N 轮 30 秒上手（可直接复制的命令块）
## 第 N 轮已知遗留 / 注意（编号列表，每条能被下一轮直接处理）
```

### 3. `05-daily/YYYY-MM-DD.md` 固定六段
目标 / 做了什么 / 动了哪些文件 / 产物 / **坑与发现（最值钱，必写）** / 下次接着做（具体到文件与行）。
新建：复制 `05-daily/_template.md`。

### 4. 施工合同 `*-roundN-brief.md` 固定七段
现状体检（表格：项 / 现状事实 / 影响）｜验收标准（每条可执行、可判定）｜实现顺序（每步可独立验收）｜测试方法（含精确命令）｜风险与注意｜开工 30 秒｜不在本轮范围。
> 验收标准写成"打开 X、点 Y、看到 Z、跑 C 命令得到 D"，不写"体验流畅"。

## 四、写作硬规则

1. **数字优先**：写"2,044,187 tri / 60 draw calls / 892 KB / 28/28 PASS"，不写"性能不错、规模很大"。
2. **命令可复现**：贴出的命令必须当时跑通过；参数、端口、目录写全。
3. **坑必须写**：踩坑的**根因**比结论值钱（例："浮空的根因是家具按等差网格摆放，没避开楼板楼梯井"）。
4. **未完成也写**：⏸ 要写等谁/等什么；❌ 要写失败现象 + 已排除项 + 下次从哪查。
5. **不写过程流水账**："调了一下午"没有信息；"把 SHADOW.on 在移动档关掉，帧时间 41→24 ms"才有。
6. **一次委托一次记录**：跨天的同一轮，日记续写，合同不改。
7. **敏感/本机信息**：写局域网 IP 时用 `192.168.x.x` 脱敏。

## 五、会话开始检查单（6 步，约 3 分钟）

```powershell
# 1. 读现状（90 秒）
cat STATUS.md
# 2. 读本轮合同（60 秒）
ls 03-notes/*round*.md        # 最新那份
# 3. 看仓库真实状态（别信文档，信 git）
git status --short; git log --oneline -5
# 4. 刷新自动事实块，确认与文档一致
node tools/status.mjs
# 5. 确认基线可跑（构建 + 体检）
cd 01-source/cielo; node build.mjs; node tools/checkall.mjs
# 6. 在 TODO 里列出本轮任务，然后才动手
```

**新会话必须能回答 4 个问题**（答不出 = 记录不合格）：
① 线上最新版本是哪个 commit / 什么状态？② 上一轮改了哪些文件、为什么？③ 本轮要做什么、验收标准是什么？④ 有哪些已知坑不能碰？

## 六、会话结束检查单（7 步，缺一不可）

```powershell
# 1. 构建 + 全量体检（PASS 才往下走）
cd 01-source/cielo; node build.mjs; node tools/checkall.mjs
# 2. 回仓库根，刷新事实块
cd ../..; node tools/status.mjs --write
# 3. 更新 05-daily/YYYY-MM-DD.md（六段写完，坑必写）
# 4. 在 HANDOFF.md **顶部**追加本轮段落（旧轮不动）
# 5. 更新 STATUS.md 的本轮进度 / 下一步 / 线上入口
# 6. 提交（见下节规范），确认工作树干净
git add -A; git status --short; git commit -m "..."; git push
# 7. 线上验证（Pages 生效约 1 分钟）：打开 STATUS.md 里的入口 URL + 移动端带 ?touch=1 再看一眼
```

## 七、提交信息规范

格式：`type(scope): 中文摘要（≤40 字）`
- type：`feat` 新功能 / `fix` 修 bug / `docs` 文档 / `perf` 性能 / `refactor` 重构 / `content` 文案与数据 / `chore` 构建与清理。
- scope：`cielo` / `celestia` / `repo` / `tools`。
- body（可选但推荐）：**为什么改 + 关键数字 + 验收命令**。例：
  ```
  feat(cielo): 安卓平板触摸层与移动质量档

  - src/touch.js：左摇杆/右拖视角/升降键/动作条（触屏才启用）
  - 质量档 ?q=low|mid|high，low 关阴影+泛光降半档；桌面 28/28 PASS
  - 验收：node tools/checkall.mjs；移动模拟 node tools/mobile-check.mjs
  ```
- 一轮一提交（或按"代码 / 文档 / 产物"拆 2–3 个）；**不提交**渲染中间帧、日志、本机配置（见 .gitignore）。
